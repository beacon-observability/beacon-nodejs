# Beacon Node.js 3.0.0

This major release adopts the Security SIEM v1 output contract pinned to
`4a30f30e1027568cfbcf8661079a072fc89bd825`. It aligns the three Beacon-owned
npm packages and telemetry version identities at 3.0.0.

## Breaking Security output change

The OTel Logs Body and optional evidence JSONL stream contain one SIEM envelope
per finding or inventory. The complete serialized v2 evidence is retained in
`message`. Consumers must parse `message` to read `schema_version`,
`event_name`, request/sink evidence, and inventory dependencies. There is no
legacy output switch or duplicate export route.

Finding `event_id` is the occurrence ID; inventory IDs are deterministic over
process, collection time, and part index. Available correlation uses `trace_id`,
`span_id`, and integer `trace_flags`. `span_id` identifies the span active at
detection, including when it is the request-entry span, and matches the OTel
LogRecord association. The old `server_span_id` and `current_span_id` fields
are absent; no server span is substituted when no invocation span is active.

Configured OTel service and tenant identity enter the envelope before evidence
compaction. Actor and IP remain empty without verified request enrichment.
Finding outcome remains `unknown` and severity remains `informational`.
Export and inventory splitting account for the final escaped envelope bytes.
Fingerprint v1, schema v2 evidence, default no-evidence filtering, and the
opt-in Security lifecycle are unchanged.

## Runtime and source boundaries

Node.js support remains 18.19+, 20.6+, 22 and 24. Opt-in Security requires
Node.js 22.22.3+ or 24.11.1+ and ESM `--import`. The inherited Contrib baseline
remains `501b1e6b5640ba5003aeadba317c9d11b941e44e`; product dependencies remain
auto-instrumentation 0.80.x and Core 2.x. Profiling continues to use native
pprof and the existing multipart HTTP uploader.

Validation and publication receipts are recorded in the GitHub Release.
The [Security source validation](../validation/security-siem-v1.md) covers
shared vectors, byte budgets, invocation spans, and a real Collector path;
Collector receipt does not establish downstream storage acceptance.

Rollback: pin all three Beacon packages to 2.0.3 and restore consumers of the
historical v2 Body. Published artifacts are immutable. Container publication
and its architecture acceptance are a separate distribution workflow.
