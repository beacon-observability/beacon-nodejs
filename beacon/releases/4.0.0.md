# Beacon Node.js 4.0.0

## Breaking Security log binding

Security now exports compact single-line schema-v2 JSON directly in the OTel
LogRecord Body. `observed_at` moves to native event time and `occurrence_id`
moves to the `event_id` log attribute. `source` remains in Body and attributes;
all other field paths, decoded values and nesting remain unchanged. There is no
SIEM envelope or `message` wrapper. Fingerprint v1 and the inventory ID algorithm
are unchanged. Queueing and retries retain event time and identity. Record byte
budgets and inventory partitioning use the final compact UTF-8 Body.

The three Beacon-owned npm packages and profiling/Security telemetry identities
are aligned at 4.0.0. Security pins specification `d9d76e5a41d974d294bb596e06918bb954319bf6`.

## Migration and scope

Update consumers to parse Body once and read event time/event ID from native
LogRecord metadata. Body-only diagnostic JSONL omits those two values. Default
`no_evidence` filtering, schema v2, fingerprint v1 and opt-in Security remain.
An active-request SIGTERM regression now validates the new binding and flushes
findings before SDK shutdown. Numeric validation predicates preserve provenance;
opt-in bounded source-site diagnostics identify unsupported calls.

Zero-code tracing support remains Node.js 18.19+, 20.6+, 22 and 24; Security
requires Node.js 22.22.3+ or 24.11.1+. Profiling retains multipart pprof HTTP export.
The adopted Contrib baseline and upstream package identities are unchanged.

Upgrade all three Beacon-owned packages together. Rollback requires pinning all
three to 3.0.0 and restoring the matching SIEM consumer. Container distribution
is separate from npm/GitHub publication. Publication and validation receipts are
recorded in this Release; Collector receipt does not prove backend persistence.
