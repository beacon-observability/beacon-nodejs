## Changes

- **Breaking:** adopt the [standard Security log binding](https://github.com/beacon-observability/beacon-security-spec/commit/d9d76e5a41d974d294bb596e06918bb954319bf6): compact, single-line schema-v2 JSON directly in LogRecord Body, without a SIEM envelope or `message` wrapper.
- Improve active-request shutdown flushing, preserve provenance through numeric validation, and add opt-in diagnostics for unsupported source calls.

## Upgrade

Update log consumers before upgrading. Parse Body once and read the relocated fields from native metadata:

| Previous field | Read from |
| --- | --- |
| Body `observed_at` | Native LogRecord event time (`time_unix_nano`) |
| Body `occurrence_id` | LogRecord `attributes.event_id` |

- All other field paths and values stay intact; `source` remains in Body and attributes. Schema v2, fingerprint v1, inventory IDs, opt-in Security, and default `no_evidence` filtering stay unchanged.
- Body budgets use final compact UTF-8 bytes; retries preserve event time and identity. Body-only diagnostic JSONL omits native time and event ID.
- Upgrade all three Beacon packages to **4.0.0** together. To roll back, restore **3.0.0** and its matching SIEM consumer.

## Distribution

- npm: `@beacon-observability/nodejs`, `profiler-nodejs`, and `security-nodejs`, all **4.0.0**.
- Zero-code tracing: Node.js **18.19+, 20.6+, 22, and 24**. Security requires **22.22.3+ or 24.11.1+**. Profiling uses HTTP multipart pprof.
- Container: `ghcr.io/beacon-observability/beacon-nodejs:4.0.0` for **amd64 and arm64**. See the [immutable digest](https://github.com/beacon-observability/beacon-nodejs/releases/download/v4.0.0/image-digest.txt).
