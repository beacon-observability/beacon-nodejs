# Beacon Node.js 1.2.0 Stable Release Acceptance Record

## Scope

Beacon Node.js `1.2.0` embeds opt-in Beacon Security and runtime SBOM support
in the existing `@beacon-observability/nodejs` zero-code preload workflow. It
also releases matching `@beacon-observability/profiler-nodejs` and
`@beacon-observability/security-nodejs` packages. Security remains disabled by
default and does not create local diagnostic files unless explicitly enabled.

## Functional Baseline

- General Beacon zero-code runtime: Node.js 18.19, 20, 22, and 24
- Beacon Security runtime: Node.js 22.22.3+ and 24.11.1+
- Security contract: schema version 1 and fingerprint version 1
- Trace export: standard OpenTelemetry auto-instrumentation and OTLP
- Profile export: receiver-compatible multipart `pprof`
- Security export: findings and runtime SBOM through OpenTelemetry Logs

## Publication Status

The source tag exists, but npm publication and the GitHub Release have not yet
completed. Beacon Node.js `1.2.0` is therefore not accepted as a public release
at the time of this record. Source and candidate validation must not be cited
as proof that public packages are available.

## Post-release Acceptance

Acceptance requires all of the following to pass against public artifacts:

- npm exposes version `1.2.0` for all three Beacon-owned packages.
- GitHub Release tag and title are exactly `v1.2.0`, the release is stable, and
  it points to the validated tag commit.
- The three attached tarballs match the pre-release SHA-256 digests.
- A clean environment installs the exact public versions without a local
  workspace or tarball fallback.
- The public `@beacon-observability/nodejs/register` preload exports a trace
  and profile from an application with no telemetry imports.
- Security remains inactive when configuration is absent.
- On a supported Node.js runtime, explicit Security configuration exports a
  finding and a runtime-SBOM event through OpenTelemetry Logs without enabling
  local diagnostic output.

Post-release results are recorded only after every check above runs against
the immutable public artifacts.

## Known Limitations

- Beacon Security requires Node.js 22.22.3+ or 24.11.1+ even though the general
  zero-code package also supports Node.js 18.19 and 20.
- Security observes bounded modeled flows and reports candidate risks rather
  than confirmed vulnerabilities.
- The current profiling ingestion path uses compatible multipart `pprof`
  rather than the OpenTelemetry Profiles signal.
- Local Security output is diagnostic evidence, not durable or cluster-wide
  delivery.
